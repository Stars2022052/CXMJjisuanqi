潮汐秘境计算器 —— 开发需求文档
一、项目定位 
做一个单文件网页工具（单个 .html，内嵌 CSS + JS，零外部依赖，双击即可在 Chrome / Edge 中离线运行）。
它是游戏《潮汐秘境》小游戏的纯辅助计算器，不是游戏本体。
网页绝不随机生成钻石布局，也不模拟游戏开局 
玩家自己在游戏里点格子，把看到的"翻开的格子坐标 + 数字 / 钻石"手动填进网页 
网页负责约束推导 + 精确概率计算 + 下一步推荐 

二、游戏规则（务必完全遵循） 
棋盘三种尺寸：
尺寸    钻石总数
8×8    20
10×10    30
12×12    45
钻石​ = 传统扫雷里的"雷" 
玩家目标是找齐并点开全部钻石（与扫雷相反，扫雷是避雷） 
点开一个格子： 
是钻石 → 显示 💎 
不是钻石 → 显示自身 3×3 范围内（周围 8 格）的钻石数量，即数字 0~8 
数字含义：该格周围8格中实际含有的钻石数 = 这个数字 
每个格子的 3×3 范围在棋盘边缘处会自然缩小（边界上的格子邻居不足 8 个） 

三、用户交互 
3.1 地图切换 
顶部提供 8×8 / 10×10 / 12×12 三个按钮，点击切换棋盘尺寸并重置棋盘。
3.2 格子标记方式 
点击任意一个格子，弹出标记菜单，可选：
数字 0 1 2 3 4 5 6 7 8 
💎 —— 标记该格为钻石 
× —— 标记该格一定不是钻石（安全格，辅助记忆） 
清除 —— 清除该格的标记，恢复为未翻开状态 
同时提供"单击涂"快捷栏（选中某工具后，点击格子直接应用，无需反复弹菜单）。
支持键盘操作：数字键 0-8、Enter 标钻石、X 标×、Delete 清除、右键快速标钻石。
3.3 工具栏 
撤销上一步：可连续撤销多步操作 
自动推导：自动把能确定的格标为 × 或 💎（见第四、五章） 
清空棋盘：重置当前棋盘 

四、核心算法 —— 确定性约束推导（必须实现） 
对每一个已翻开的数字格，做如下计算：
剩余钻石数 = 数字值 - 该格3×3范围内已标为💎的格子数
未确定格数 = 该格3×3范围内状态为"未翻开"的格子数
推导规则（必须严格实现）：
1.若 剩余钻石数 == 0：则这些未确定格全部自动标为 ×（它们周围一定没有钻石了） 
2.若 剩余钻石数 == 未确定格数：则这些未确定格全部标为 💎（它们全是钻石） 
3.若 未确定格数 == 0：该数字格已被完全满足，可忽略 
4.否则：该格提供的是概率约束，进入第五章计算 
推导必须迭代执行（链式反应）：当一个格被标为 × 或 💎 后，要重新扫描所有数字格，可能产生新的确定推导。直到没有新变化为止。
典型例子（开发者必须验证通过） 
例子 A：(7,4) 是数字 1，(8,4) 已标为 💎
剩余钻石 = 1 - 1 = 0 
(7,4) 周围其余 7 个未翻开格全部标为 × 
例子 B：(7,4) 是数字 2
剩余钻石 = 2 - 0 = 2 
未确定格 = 7 
暂不能确定为钻石或 ×，但提供概率约束（见第五章） 
例子 C（交叉约束）：
上方数字格是 3，其右上方、右边已标 ×，下方、右下方已翻开（无钻），则上、左上、左、左下 4 格中必有 3 颗钻石​ → 这 4 格概率各 75% 
下方数字格是 3，右下方已标 💎，右方已翻开无钻，下方已标 ×，则还剩 2 颗钻石分布在左上方和左方（各 75%），左下方出现概率 = 200% - 2×75% = 50% 
⚠️ 开发者注意：例子 C 说明概率不能只按单个数字平均，必须做多数字交叉约束修正，否则算不出 75% 和 50%。

五、概率计算（必须精确，不能估算） 
5.1 目标 
对每个"未翻开"格子，计算：
在所有满足当前所有数字约束的合法配置中，该格是钻石的配置数 / 总合法配置数
这才是数学上正确的概率。
5.2 必须使用的算法：全枚举回溯 / SAT 求解 
严禁使用"局部平均""全局密度""启发式加权"等近似算法，那些都不精确。
正确做法：
1.先用第四章做确定性约束传播，标出所有能确定的 × 和 💎 
2.收集剩下的未确定格（自由变量）和尚未满足的数字约束 
3.用回溯枚举（bitmask 或 DFS + 剪枝）遍历所有合法赋值，对每个约束在赋值过程中实时校验： 
某格已确定钻石数 > 数字 → 剪枝 
某格已确定钻石数 + 剩余未填格数 < 数字 → 剪枝 
4.统计每个未确定格在合法解中"是钻石"的频率 → 精确概率 
5.可选：加上"全局钻石总数"约束（总钻石数不超过地图钻石总数），进一步提高精度 
5.3 性能兜底 
未确定格 ≤ 16 时：全枚举，结果精确 
未确定格 > 16 时（如开局）：可暂时用"全局密度 = 剩余钻石 / 未确定格数"作为近似，但必须在界面上明确标注"近似模式"，告知用户此时不精确 
一旦用户继续填入格子、未确定格降到 16 以下，立即切换回精确模式 
也可直接用 python-sat 等 SAT 库做求解（若允许引入库） 
5.4 概率显示 
每个未翻开格子显示 百分比整数（如 75%、50%、32%） 
数字需随概率变化颜色（见第六章） 

六、UI 设计规范（必须严格还原） 
6.1 棋盘 
格子尺寸约 32×32px（不要做大格子） 
圆角、小间距（约 3px） 
棋盘居中显示 
6.2 格子样式 
未翻开格子（显示概率）：
白底 
虚线边框，边框颜色随概率分级： 
低概率（< 20%）→ 蓝色边框 + 蓝色数字 
中概率（20% ~ 50%）→ 棕色边框 + 棕色数字 
高概率（≥ 50%）→ 红色边框 + 红色数字 
格子内部显示百分比数字（如 32%） 
已翻开数字格：​ 白底，显示数字，数字按值上色（1蓝、2绿、3橙、4紫、5红等）
已标 💎：​ 黄色底 + 橙色边框
已标 ×：​ 灰色底
6.3 下一步推荐（核心功能） 
推荐目标是找钻石，所以优先推荐钻石概率最高的格子 
若有多个并列最高，优先推荐被最多数字格包围的那个（信息量大，更容易触发连锁推导） 
推荐格子必须有明显视觉标识： 
实线边框（比普通格子更粗） 
红色 
加 呼吸闪烁动画（CSS @keyframes 控制 scale + box-shadow 循环） 
6.4 布局结构 
[标题] 潮汐秘境计算器
[地图切换 8×8 | 10×10 | 12×12]  [剩余钻石 / 已用 / 已填]
[单击涂快捷栏]
[棋盘网格]
[底部提示区]
  下一步推荐文案（推荐点开 X行Y列，概率 XX%）
  [必定是钻石 X] [必定不是钻石 X] [待定 X]
  [撤销] [自动推导] [清空棋盘]

预期：左上方、左方为 75%，左下方为 50%

存在高概率格时，推荐格必须有红色实线边框 + 呼吸动画

测试 5（撤销）
